# 要件定義書

## イントロダクション

「my_roll_model」アプリケーションにおいて、登録済みロールモデル（キャラクター）の情報を修正（更新）および削除できる機能を実装する。現状はキャラクターの新規登録と一覧表示のみ対応しており、一度登録した情報の変更・削除ができない。本機能により、ユーザーはロールモデルのライフサイクルを完全に管理できるようになる。

### 現状の実装状態

- **バックエンド**: `DELETE /characters/:id` エンドポイントは実装済み。`PUT /characters/:id`（更新）は未実装。
- **フロントエンド**: 編集・削除の UI は未実装。一覧表示は読み取り専用。

## 要件

### 要件 1: キャラクター更新 API

**目的:** バックエンド開発者として、キャラクター情報を更新する REST API エンドポイントを提供したい。それにより、フロントエンドからの編集リクエストを処理できる。

#### 受け入れ基準

1. The バックエンド shall `PUT /characters/:id` エンドポイントを提供し、`{ name, description }` の JSON リクエストボディを受け付ける
2. When 有効なリクエストが送信された場合, the API shall 対象キャラクターの `name` と `description` を更新し、200 ステータスと成功メッセージを返す
3. When 名前が空文字の場合, the API shall 400 ステータスとエラーメッセージを返す
4. If 指定された ID のキャラクターが存在しない場合, the API shall 404 ステータスとエラーメッセージを返す
5. If データベースエラーが発生した場合, the API shall 500 ステータスとエラーメッセージを返す

### 要件 2: キャラクター編集 UI

**目的:** ユーザーとして、登録済みロールモデルの名前と説明を変更したい。それにより、情報の誤りを修正したり、より適切な説明に更新できる。

#### 受け入れ基準

1. The キャラクター一覧の各カード shall 「編集」操作ボタンを表示する
2. When ユーザーが編集ボタンを押した場合, the UI shall キャラクターの現在の名前と説明が入力済みの編集フォームを表示する
3. The 編集フォーム shall 新規登録フォームと同じバリデーションルール（名前必須、255文字以内）を適用する
4. The 編集フォーム shall 「保存」ボタンと「キャンセル」ボタンを表示する
5. When ユーザーがキャンセルボタンを押した場合, the UI shall 編集フォームを閉じて元の表示に戻る

### 要件 3: キャラクター更新（API 連携）

**目的:** ユーザーとして、編集した内容をサーバーに保存したい。それにより、変更が永続化される。

#### 受け入れ基準

1. When ユーザーが有効な入力で保存ボタンを押した場合, the フロントエンド shall `PUT /characters/:id` API に `{ name, description }` を JSON で送信する
2. When API が正常レスポンス（200）を返した場合, the 編集フォーム shall 閉じて、一覧の該当カードを更新後の内容で表示する
3. When API が正常レスポンス（200）を返した場合, the UI shall 成功メッセージを表示する
4. If API がエラーレスポンスを返した場合, the 編集フォーム shall エラーメッセージを表示し、フォームを開いたまま維持する
5. While API リクエスト送信中, the 保存ボタン shall ローディング状態を表示し、二重送信を防止する

### 要件 4: キャラクター削除 UI

**目的:** ユーザーとして、不要になったロールモデルを削除したい。それにより、一覧を整理できる。

#### 受け入れ基準

1. The キャラクター一覧の各カード shall 「削除」操作ボタンを表示する
2. When ユーザーが削除ボタンを押した場合, the UI shall 確認ダイアログを表示し、キャラクター名を含む削除確認メッセージを提示する
3. The 確認ダイアログ shall 「削除する」ボタンと「キャンセル」ボタンを表示する
4. When ユーザーがキャンセルボタンを押した場合, the UI shall 確認ダイアログを閉じて何も変更しない

### 要件 5: キャラクター削除（API 連携）

**目的:** ユーザーとして、削除操作がサーバーに反映されてほしい。それにより、データが確実に消去される。

#### 受け入れ基準

1. When ユーザーが確認ダイアログで「削除する」を押した場合, the フロントエンド shall `DELETE /characters/:id` API にリクエストを送信する
2. When API が正常レスポンス（200）を返した場合, the 一覧 shall 該当キャラクターを除外して再表示する
3. When API が正常レスポンス（200）を返した場合, the UI shall 削除成功メッセージを表示する
4. If API がエラーレスポンスを返した場合, the UI shall エラーメッセージを表示する
5. While API リクエスト送信中, the 削除ボタン shall ローディング状態を表示し、二重送信を防止する

### 要件 6: フロントエンド API クライアント拡張

**目的:** フロントエンド開発者として、更新・削除用の API クライアント関数を用意したい。それにより、コンポーネントから一貫したインターフェースで API を呼び出せる。

#### 受け入れ基準

1. The API クライアント（`lib/api.ts`） shall `updateCharacter(id, data)` 関数を提供し、`PUT /characters/:id` へのリクエストを行う
2. The API クライアント（`lib/api.ts`） shall `deleteCharacter(id)` 関数を提供し、`DELETE /characters/:id` へのリクエストを行う
3. The 各関数 shall 既存の `createCharacter` と同様のエラーハンドリングパターンを適用する
4. The `updateCharacter` 関数 shall `UpdateCharacterRequest` 型（`{ name: string; description?: string }`）を引数として受け取る
