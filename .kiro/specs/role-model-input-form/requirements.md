# 要件ドキュメント

## イントロダクション

「my_roll_model」のフロントエンド（Next.js App Router）に、ロールモデルとなるキャラクターの情報を入力・登録できる画面を実装する。バックエンドの `POST /characters` API と連携し、名前（name）と説明（description）を送信してキャラクターを作成する。加えて、登録済みキャラクターを `GET /characters` API から取得し一覧表示する。

## 要件

### 要件 1: キャラクター入力フォーム

**目的:** ユーザーとして、ロールモデルの名前と説明を入力できるフォームが欲しい。それにより、自分の理想像を言語化して記録できる。

#### 受け入れ基準

1. The フォーム画面 shall 「名前」テキスト入力フィールドと「説明」テキストエリアを表示する
2. The 「名前」フィールド shall 最大255文字の入力を受け付ける
3. The 「説明」フィールド shall 複数行のテキスト入力を受け付ける
4. The フォーム shall 各フィールドにプレースホルダーテキストを表示して入力内容を案内する

### 要件 2: 入力バリデーション

**目的:** ユーザーとして、不正な入力時にエラーメッセージを確認したい。それにより、正しい情報を登録できる。

#### 受け入れ基準

1. When ユーザーが名前を空のまま送信ボタンを押した場合, the フォーム shall 「名前は必須です」というエラーメッセージを表示する
2. When ユーザーが名前に255文字を超える値を入力した場合, the フォーム shall 「名前は255文字以内で入力してください」というエラーメッセージを表示する
3. While バリデーションエラーが存在する間, the 送信ボタン shall 無効化された状態を維持する、またはエラーメッセージを表示して送信を阻止する

### 要件 3: キャラクター登録（API連携）

**目的:** ユーザーとして、入力したロールモデル情報をサーバーに保存したい。それにより、データが永続化され後から参照できる。

#### 受け入れ基準

1. When ユーザーが有効な入力で送信ボタンを押した場合, the フロントエンド shall `POST /characters` API に `{ name, description }` を JSON で送信する
2. When API が正常レスポンス（200）を返した場合, the フォーム shall 入力フィールドをクリアし、成功メッセージを表示する
3. When API が正常レスポンス（200）を返した場合, the キャラクター一覧 shall 新しく登録されたキャラクターを反映して更新される
4. If API がエラーレスポンスを返した場合, the フォーム shall ユーザーにエラーメッセージを表示する
5. While API リクエスト送信中, the 送信ボタン shall ローディング状態を表示し、二重送信を防止する

### 要件 4: キャラクター一覧表示

**目的:** ユーザーとして、登録済みのロールモデル一覧を確認したい。それにより、自分が設定した理想像を振り返りできる。

#### 受け入れ基準

1. When ページが読み込まれた場合, the フロントエンド shall `GET /characters` API からキャラクター一覧を取得して表示する
2. The 一覧 shall 各キャラクターの名前と説明を表示する
3. If キャラクターが1件も登録されていない場合, the 一覧エリア shall 「まだロールモデルが登録されていません」という空状態メッセージを表示する
4. If API からのデータ取得に失敗した場合, the 一覧エリア shall エラーメッセージを表示する

### 要件 5: レスポンシブUI

**目的:** ユーザーとして、PC・モバイル両方で快適に操作したい。それにより、デバイスを問わず利用できる。

#### 受け入れ基準

1. The 画面レイアウト shall モバイル（~640px）、タブレット（641px~1024px）、デスクトップ（1025px~）の各ブレイクポイントに適応する
2. The フォームと一覧 shall Tailwind CSS のユーティリティクラスを使用してスタイリングされる
3. The UI shall ダークモードとライトモードの両方に対応する
