# 実装計画

- [x] 1. APIクライアント層の構築
- [x] 1.1 キャラクターデータの型定義とAPI通信関数の実装
  - バックエンドのキャラクターエンティティに対応する型（id, name, description）を定義する
  - バックエンドのベースURLを環境に応じて切り替えられるよう構成する
  - キャラクター一覧を取得する関数を実装し、レスポンスのJSON解析とエラーハンドリングを行う
  - キャラクターを新規作成する関数を実装し、名前と説明をJSON形式でPOSTする
  - API通信失敗時（ネットワークエラー、4xx/5xxレスポンス）にErrorをthrowする共通エラー処理を組み込む
  - _Requirements: 3.1, 4.1_

- [x] 2. キャラクター一覧表示コンポーネントの実装
- [x] 2.1 (P) 一覧取得・表示の基本機能を構築
  - ページ読み込み時にAPIからキャラクター一覧を自動取得する
  - 各キャラクターの名前と説明をカード形式で表示する
  - 外部からのリフレッシュ通知を受け取り、一覧データを再取得する仕組みを実装する
  - _Requirements: 4.1, 4.2_

- [x] 2.2 (P) 一覧の空状態・エラー状態の処理
  - キャラクターが0件の場合に「まだロールモデルが登録されていません」という案内メッセージを表示する
  - API取得中のローディング状態を表示する
  - API取得失敗時にエラーメッセージを一覧エリア内に表示する
  - _Requirements: 4.3, 4.4_

- [x] 3. キャラクター入力フォームコンポーネントの実装
- [x] 3.1 (P) 入力フォームのUI構築
  - 名前入力フィールド（最大255文字）と説明入力用の複数行テキストエリアを配置する
  - 各フィールドにプレースホルダーテキストを設定して入力内容を案内する
  - 送信ボタンを配置する
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 3.2 クライアントサイドバリデーションの実装
  - 名前が空の場合に「名前は必須です」というエラーメッセージをフィールド下部に表示する
  - 名前が255文字を超える場合に「名前は255文字以内で入力してください」というエラーメッセージを表示する
  - バリデーションエラーが存在する間は送信を阻止する
  - _Requirements: 2.1, 2.2, 2.3_

- [x] 3.3 フォーム送信・API連携とフィードバック処理
  - 有効な入力で送信ボタンを押した際にAPIクライアント経由でキャラクター作成リクエストを送信する
  - API送信中は送信ボタンをローディング状態にし、二重送信を防止する
  - 登録成功時にフォームをクリアし、成功メッセージを表示する
  - 登録成功時に一覧コンポーネントのリフレッシュをトリガーする
  - APIエラー時にフォーム上部にエラーメッセージを表示する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [x] 4. メインページの統合とレスポンシブ対応
- [x] 4.1 メインページにフォームと一覧を統合
  - 既存のデフォルトトップページをロールモデル管理画面に置き換える
  - フォームコンポーネントと一覧コンポーネントを配置し、登録成功時の一覧リフレッシュを連携する
  - _Requirements: 3.3_

- [x] 4.2 レスポンシブレイアウトとテーマ対応
  - モバイル（~640px）、タブレット（641px~1024px）、デスクトップ（1025px~）の各ブレイクポイントに適応するレイアウトを構築する
  - Tailwind CSSのユーティリティクラスを使用して全コンポーネントをスタイリングする
  - ダークモードとライトモードの両方にUIを対応させる
  - _Requirements: 5.1, 5.2, 5.3_
